# LoginWatch

[Демо Github Pages](https://greymolnia.github.io/LoginWatch/)

LoginWatch - это веб-приложение для поиска подозрительных последовательностей входа в аккаунты корпоративного портала. Мы разрабатываем его для системного администратора небольшого предприятия на 20–100 сотрудников, где нет отдельного отдела информационной безопасности.

Когда событий входа много, вручную просматривать журнал неудобно. В нашем приложении пользователь загружает файл, выбирает правила проверки и получает список предупреждений. У каждого предупреждения есть объяснение, связанные события и рекомендации, что проверить дальше. Для демонстрации используются вымышленные аккаунты и синтетические журналы.

## Как работает приложение

Сейчас в LoginWatch реализованы три правила. Первое находит серию неудачных входов в один аккаунт. Второе ищет ошибки входа в несколько разных аккаунтов с одного IP-адреса. Третье отмечает успешный вход, которому предшествовала серия ошибок в том же аккаунте.

По умолчанию включены все три правила, но их можно запускать отдельно. Для каждого правила настраиваются порог и временное окно. Начальные значения - 5 ошибок или разных аккаунтов за 10 минут. Это предварительные настройки для демонстрации, а не универсальные значения для любой организации.

В первом правиле учитываются ошибки одного аккаунта независимо от IP. Во втором считаются именно разные аккаунты: несколько ошибок в одной записи не увеличивают их количество. В третьем проверяются ошибки за выбранное время перед успешным входом. После любого успешного входа серия ошибок этого аккаунта сбрасывается. При этом успешный вход не отменяет проверку других ошибок с общего IP по второму правилу.

После анализа приложение показывает количество обработанных событий, общее число предупреждений и результаты каждого выбранного правила. В карточке предупреждения можно раскрыть исходные события или перейти к ним на временной шкале. Повторяющиеся срабатывания одной серии в первых двух правилах объединяются в эпизод. Поэтому его общая длительность может быть больше выбранного окна.

На временной шкале события расположены в хронологическом порядке, время приведено к UTC. Можно посмотреть весь журнал или отдельный эпизод. На шкале и в раскрытой карточке сначала отображаются до 50 событий, остальные можно показать кнопкой. Фильтр шкалы меняет только просмотр. В отчёт входят все связанные события.

Результат можно скачать в TXT или JSON. В отчёте сохраняются название исходного файла, время проверки, настройки, предупреждения, причины, рекомендации и связанные события. При изменении журнала или настроек предыдущий результат очищается, поэтому перед скачиванием нужно снова запустить проверку.

## Как запустить

Скачайте репозиторий через **Code → Download ZIP**, распакуйте архив и откройте `index.html` в современном браузере. Все файлы проекта должны оставаться рядом, как в репозитории. Для работы приложения не требуется устанавливать пакеты или запускать сервер.

Чтобы быстро посмотреть результат, нажмите **«Успех после ошибок»**, оставьте режим **«Все три правила»** и нажмите **«Проверить журнал»**. При начальных настройках приложение обработает 7 событий и покажет 2 предупреждения: серию ошибок и успешный вход после неё. Это два предупреждения об одной последовательности, а не подтверждение двух отдельных атак.

Для проверки своего примера нажмите **«Выбрать файл журнала»** и загрузите JSON или CSV. Готовые файлы находятся в папке `samples`.

## Какие данные принимает LoginWatch

Каждое событие содержит пять строковых полей: `id`, `timestamp`, `account`, `ip`, `result`. Поле `id` должно быть уникальным, `timestamp` — содержать дату и время с часовым поясом, `account` - имя аккаунта, `ip` - IPv4-адрес. Для `result` допустимы значения `failure` и `success`.

JSON-файл должен содержать массив событий. В CSV первая строка содержит заголовки `id,timestamp,account,ip,result`. Их порядок можно менять. Поддерживаются разделители запятая и точка с запятой, кодировка UTF-8, поля в кавычках. Заголовки нужно записывать без кавычек. Ограничения текущей версии: до 5 МБ и до 20 000 событий в одном файле.

Перед анализом приложение проверяет структуру и значения. Если нет нужного столбца, повторяется ID, указан неизвестный результат входа или несуществующая календарная дата, пользователь получает сообщение об ошибке. Скачанный JSON-отчёт имеет другую структуру и не предназначен для загрузки вместо журнала.

## Как мы проверяем проект

В проекте есть 42 автоматические проверки правил, чтения файлов, формирования отчётов и временной шкалы. Если установлен Node.js, их можно запустить из папки проекта:

```bash
node --test analyzer.test.cjs io.test.cjs timeline.test.cjs
node qa/run.cjs . evidence
```

Дополнительный набор содержит 39 проверок. Он повторяет оценку на 20 размеченных журналах, проверяет пограничные случаи импорта и сохраняет протокол в `evidence/`. На учебной выборке с порогом 5 и окном 10 минут обнаружены 10 из 10 подозрительных сценариев. На 10 контрольных сценариях предупреждений не было.

В [отчёте от 22 ноября](docs/testing/report.txt) сохранены результаты более раннего браузерного и модульного прогона на коммите `a147061`. Тогда проверка невозможной даты LW-001 завершалась ошибкой. После исправления модульная проверка S05 покрывает также високосные годы, часовые пояса и миллисекунды.

Для отдельного браузерного прогона нужны Playwright и Chrome. После установки выполните `node qa/browser.cjs . evidence/browser`. При локальном запуске скрипт проверяет импорт, переключение правил, шкалу и скачивание отчётов.

Для повторения проверок можно использовать `rule3_suspicious.csv`: при всех трёх правилах и начальных настройках ожидаются 2 предупреждения. В `rule2_suspicious.csv` ожидается одно предупреждение по второму правилу, а в `rule2_different_ips.csv` — ни одного. Файлы `invalid_missing_column.csv` и `invalid_result.csv` специально содержат ошибки. В `timeline_shuffled.json` события перемешаны для проверки сортировки, а `timeline_55_events.json` нужен для проверки длинного списка.

Файл `normal.json` сохранён для проверки первого правила. Для второго правила он считается подозрительным, потому что содержит ошибки разных аккаунтов с одного IP. Для примера без предупреждений по всем правилам используйте кнопку **«Обычные входы»** или файл `rule2_different_ips.csv`.

## Ограничения и дальнейшая работа

Приложение обрабатывает файлы в браузере, не отправляет журналы на сервер, не подключается к реальным аккаунтам и не блокирует пользователей. Предупреждение означает, что последовательность стоит проверить. Например, сотрудник мог несколько раз ошибиться в пароле, а общий IP может принадлежать офисной сети или VPN. По одному журналу нельзя уверенно утверждать, что произошла атака.

Учебная цель — обнаружить как минимум 9 из 10 подозрительных сценариев и не допустить больше одного ложного предупреждения в контрольной группе. На размеченной синтетической выборке цель достигнута. Результат относится к подготовленным сценариям и стандартным настройкам.

Код страницы и интерфейса находится в `index.html`, `styles.css` и `app.js`. Правила реализованы в `analyzer.js`, работа с файлами и отчётами - в `io.js`, временная шкала - в `timeline.js`.
